## 3. Methodology

1. **Ingest & clean** — parse logs, normalize timestamps, drop obvious junk
2. **Baseline** — normal login volume, peak hours, top users/IPs
3. **Detection rules** (simple, explainable — not ML):
   - N failed logins from one IP within M minutes → possible brute force
   - Success after many failures → possible account compromise
   - Privileged account anomalies
   - Activity outside expected hours (if defined)
4. **Triage** — confirm with evidence snippets; reduce false positives
5. **Risk rating** — Critical / High / Medium / Low
6. **Map to controls** — CIA triad + NIST CSF (Identify / Protect / Detect / Respond / Recover)

### Detection rules used

| Rule ID | Condition | Suspected activity |
|---------|-----------|--------------------|
| R1 | ≥ 10 failed logins from same IP in 5 min | Brute force |
| R2 | ≥ 5 failures then 1 success for same user | Credential compromise |
| R3 | Admin/root success from new/rare IP | Privileged account misuse |
| R4 | Logins 00:00–05:00 local (if policy exists) | Anomalous access |

*(Adjust thresholds to your dataset and document why.)*

## 6. Recommendations (priority order)

1. **Protect:** Enforce MFA + account lockout after N failures  
2. **Detect:** Alert on Rule R1/R2 in SIEM / log platform  
3. **Protect:** Least privilege — limit interactive admin logins  
4. **Identify:** Asset & account inventory for privileged users  
5. **Respond:** Playbook for “success after failures” (reset, review sessions, notify)  
6. **Recover:** Backup/verify logging pipeline so evidence is retained
